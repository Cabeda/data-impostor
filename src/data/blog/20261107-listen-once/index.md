As I've gotten to use more of voice chat, I've found AI generated text too verbose. The line between correct and plausible is very thin. As an experiment I started prompting the agents to write more and more in the way that it does when I use the voice chat.

Why do that? Because I find the spoken text shorter, cleaner and actually understandable. As is becoming the norm these days we see a pattern, I decided to write it into a new skill that I run now in tandem with [/unslop](https://www.skills.sh/cursor/plugins/unslop).

In short what I ask is:

> Write for a listener who cannot look back. After one listen, the intended audience should understand the main point, what happens next, and any conditions that affect the decision.

As I've been using [skills.sh](https://www.skills.sh/), I've decided to make my first contribution. To have a skill listed on the website we need:

1. A [github repo](https://github.com/cabeda/listen-once)
2. A README.md
3. A SKILL.md

Once tha was done, after a while it appeared listed on [listen-once](https://www.skills.sh/cabeda/listen-once/listen-once) (possibly after I installed it through the app). Now, I can just install it on all my devices with:

```sh
npx skills add https://github.com/cabeda/listen-once --skill listen-once -g
```

## Where I use the skill

I frequently run this to help me on the following cases:

1. Understand a concept
2. Write issues
3. Write code-review comments

There's space for both comprehensive descriptions but currently I think that the main goal of most texts is to be down to earth and focus on ensuring that whoever is reading it quickly understands it.

## Disclaimer

I make it a point to write everything on my blog (I have 1 article to explain voice mode that is marked as ai generated). It's my way of improving my writing skills and to think. Revisions are necessary and I use AI to put himself in the position of a reader and make critics which I use to revision my drafts. The skill above is when we want the outputs of AI to be useful.
